# Changelog

## 2.0.0 — unreleased

The plugin becomes a fire analysis pipeline (plan in `docs/DESIGN.md`) and is renamed the **Wildfire Analysis Toolkit**: plugin name, Toolbox provider and zip folder (`wildfire_analysis_toolkit`). The provider id stays `fireanalysis`, so algorithm ids are unchanged. The standalone script, Burn severity summary 1.1.0, is unchanged.

- **Find HLS scenes** (`fireanalysis:findhlsscenes`, plugin only). Searches NASA's HLS v2.0 archive (Landsat 8/9 L30 and Sentinel-2 S30) over an area of interest and date range, and returns one footprint per granule with its tile, date, scene cloud cover and the share of the AOI it covers. No login needed. Optionally measures each date's clear share inside the AOI from Fmask (needs the login; six dates at a time).
- **Severity map (PDF)** (`fireanalysis:severitymap`, plugin only). A4 map of the MTBS classes with burned area, sub-areas, legend, scale bar, north arrow, area summary and a provenance note from the raster metadata; PDF and PNG.
- **Burn severity (whole pipeline)** (`fireanalysis:burnseveritypipeline`, plugin only). The whole pipeline in one step, from NASA HLS or Planetary Computer Landsat / Sentinel-2: image pair, pre/post NBR, dNBR with offset, MTBS classes, area summary per zone, a class map picture, and an HTML/JSON report (with a bar chart and the map) of the inputs (the burned-area and sub-area layers with their sources, feature counts and the burned area's size; a temporary or selection-only layer is flagged), every scene, calibration, threshold (with a cross-check from the other estimate method) and warning, all in one output folder.
- **Pipeline: drafted burned area.** A new *Burned area* option (`PERIMETER_MODE`: 0 as given, 1 drafted from dNBR inside the given polygons) lets the pipeline take a generous outline around the fire. The outline sets the imagery window and the offset ring; the burned area is drafted from the dNBR inside it (Advanced `DRAFT_THRESHOLD` 0.05, `DRAFT_MIN_AREA` 20 ha), saved as `perimeter_draft.gpkg`, and used for the classes, the summary and the map. The report gives the draft's size and share of the outline. *Draft burned-area perimeter* gains *Clip to the seed polygons* (`CLIP`) for this.
- **Suggest image pairs** (`fireanalysis:suggestimagepairs`, plugin only). Ranks pre/post-fire dates (HLS, or Planetary Computer Landsat or Sentinel-2) for a fire by the MTBS rules: post-fire soon after the fire (initial) or the next growing season (extended), pre-fire in the same season of earlier years, both clear inside the burned area (from Fmask), ranked by season match. Its granule lists go straight into Fetch HLS NBR.
- **Fetch HLS NBR** (`fireanalysis:fetchhlsnbr`, plugin only). Reads only the AOI window (plus a 3 km buffer) of the chosen granules from NASA Earthdata, mosaics the tiles on a 30 m grid snapped to whole pixels, masks the chosen Fmask classes, and writes NBR in raw units, plus an optional SWIR2/NIR/red reflectance stack and the Fmask window. The same AOI and CRS always give the same grid, so pre- and post-fire NBR line up. The Earthdata login is read from `~/.netrc`. Scenes come from the Find HLS scenes layer or as a list of granule ids.
- **Find / Fetch Landsat / Sentinel-2 (Planetary Computer)** (`fireanalysis:findplanetaryscenes`, `fireanalysis:fetchplanetarynbr`, plugin only). Landsat Collection 2 Level-2 (Landsat 4–9, from 1982) and Sentinel-2 L2A from Microsoft Planetary Computer, no account needed: search with an optional AOI clear share, then calibrated, masked NBR for the AOI window on the shared grid. Opens fires before HLS (2013).
- **Prepare local scene NBR** (`fireanalysis:preparelocalnbr`, plugin only). Calibrated, masked NBR from downloaded Landsat Collection 2 Level-2 (scene or US ARD tile, Landsat 4–9) or Sentinel-2 L2A files, on the same grid as Fetch HLS NBR. Reads the scale and offset from the MTL, ARD or `MTD_MSIL2A.xml` metadata; applies the Sentinel-2 −1000 BOA offset by date when the metadata is missing, and stops for older scenes without it. Masks from QA_PIXEL or SCL. Mosaics several tiles of one date.
- **Build dNBR** (`fireanalysis:builddnbr`, plugin only). dNBR, RdNBR and RBR from pre- and post-fire NBR on the post-fire grid, with the dNBR offset of unburned land: the median in a ring outside the burned area (default), inside unburned-sample polygons, or a fixed value. RdNBR and RBR use the offset; dNBR is written without it unless asked. Warns when the offset or its spread is large, or when the "unburned" sample looks burned (incomplete or clipped burned-area polygons). The offset is also returned as numbers for models.
- **Draft burned-area perimeter** (`fireanalysis:draftperimeter`, plugin only). Burned-area polygons from dNBR (threshold, patch sieve, hole fill, optional seed polygons), as a starting point when no perimeter exists. Mean IoU 0.69–0.73 against 18 MTBS perimeters.
- **Classify severity (MTBS classes)** (`fireanalysis:classifyseverity`, plugin only). The MTBS thematic classes (`dnbr6`: unburned to low, low, moderate, high, increased greenness, non-mapping) inside the burned area, with given or estimated thresholds, and a `.qml` style with the MTBS colors. Estimates come from the median thresholds of nearby MTBS fires (online; default) or from the fire's own offset and RdNBR.
- Every imagery and severity algorithm refuses a scenes layer (the footprints from a *Find ... scenes* run) given as the area of interest, burned area, unburned sample or seed, with a message naming the mistake; before, the tile footprints' union failed later as an area too large to read. That message now gives the size in km. In the Find algorithms the optional AOI clear share no longer fails the search: the scenes come back without it, with a warning.
- In the plugin, Burn severity summary moves to a **Severity** group; its id and parameters are unchanged.
- Checked against Lab 6: HLS gives a dNBR inside the burned area that matches a correctly calibrated rebuild from the lab's own Sentinel-2 and Landsat 9 files. The lab's `dNBR.tif` turns out to combine Sentinel-2 NBR without the −1000 `BOA_ADD_OFFSET` and Landsat 9 NBR from unscaled DN, which is why it shows almost no High severity.
- **Validated against MTBS.** `dev/mtbs_validation.py` reruns published MTBS fires from HLS with MTBS's dates, perimeters and thresholds and compares the classes pixel by pixel; `dev/threshold_study.py` scores threshold-estimation rules against MTBS's analyst choices. Over 17 Southwest fires from 2022–2024, our classes with MTBS's thresholds agree with MTBS at a mean kappa of 0.775 (88.7 % of pixels); with estimated thresholds, 0.56. Six fires from 2000–2012 through Planetary Computer Landsat give a mean kappa of 0.69. Results are in the README and `docs/DESIGN.md`.
- `dev/online_test.py` runs the whole chain against the live HLS archive: find, fetch pre and post, build dNBR, summarize, then the one-step pipeline with given granules and with a suggested pair, and Planetary Computer against HLS. `dev/pipeline_test.py` tests the offline algorithms: Build dNBR reproduces `testdata/dnbr.tif` exactly and matches an independent offset calculation; Prepare local scene NBR is checked on synthetic Landsat and Sentinel-2 products with known DN; Classify severity on its class rules and estimates. `dev/run_headless.sh` passes extra arguments to the script. `dev/run_headless.sh` takes the script to run as an optional second argument.

## 1.1.0 — 2026-10-06

- **RdNBR and RBR.** A new *Severity index and thresholds* option adds RdNBR (Miller & Thode 2007) and RBR (Parks et al. 2014), computed from the dNBR and a new optional *Pre-fire NBR raster*, each with its published four-class thresholds. The pre-fire NBR is resampled to the dNBR grid. dNBR with the USGS thresholds stays the default.
- **One zone, or many.** The sub-area layer (formerly *Watershed boundary*) is optional: leave it empty to summarize the burned area alone. Set the new *Sub-area name field* to get one zone per value, for example one per sub-watershed. Each zone's summary fields use a short code taken from its name. Sub-areas with no burned area inside, or with no name, are skipped with a warning.
- **Stops on rescaled input.** With the preset thresholds, the tool refuses a dNBR raster whose values look rescaled to 0–1 or scaled ×1000, and a pre-fire NBR outside −1 to 1, instead of producing wrong classes. Custom thresholds turn this into a warning.
- **Custom thresholds moved to Advanced.** The threshold table and class names are now optional overrides; empty means the preset for the chosen index. Two new Advanced options set the summary field codes for zone A and zone B (default `db` and `ba`, as before).
- **Fixed: the severity raster was written as Float32**, not Int32: the `DATA_TYPE` option index was wrong (5 is Float32; Int32 is 3). The index is now looked up by name. Pixel counts are unchanged, and Zonal Histogram no longer warns about a floating-point raster.
- **Fixed: the severity raster could have no CRS.** In a QGIS 4.2.3 desktop session, Reclassify by Table wrote the classes without a CRS for the Lab 6 dNBR (an ArcGIS-exported GeoTIFF), though the same run headless kept it. The tool now checks the output and writes the dNBR's CRS into it when it is missing.
- **Fixed: on QGIS versions older than 3.30**, the summary table could not be created (a compatibility fallback called itself).
- Tested headless on QGIS 3.44 and 4.2. The minimum supported version is now QGIS 3.40.
- Also available as a QGIS plugin: `python3 dev/build_plugin.py` builds a zip with a **Fire Analysis** Processing provider (algorithm id `fireanalysis:burnseveritysummary`).
- Test data in `testdata/` (a clip around the Bright Angel watershed), with `dev/make_testdata.py` to rebuild it. `dev/smoke_test.py` now checks every mode and the error cases, inside QGIS or headless through `dev/run_headless.sh`.

## 1.0.0 — 2026-10-06

- First release. One Processing tool (**Scripts › Fire Analysis › Burn severity summary**, id `script:burnseveritysummary`) that builds a burned-area zone and a watershed sub-zone, classifies raw dNBR into USGS (Key & Benson 2006) severity classes, counts pixels per class with Zonal Histogram, and writes a one-row-per-class summary table (percent, hectares and acres for each zone) for layout charts.
- Editable threshold table and class names; pixel area read from the raster.
- `dev/smoke_test.py` checks results against the Dragon Bravo / Bright Angel Lab 6 counts.
